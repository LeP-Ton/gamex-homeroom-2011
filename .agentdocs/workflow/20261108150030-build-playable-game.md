# 完整单机高三班主任模拟器

## 背景与目标

- 对应会话-1 起，依据用户提供的 V1.0 完整需求，从空仓库实现可玩游戏。
- 交付模拟核心、桌面应用、100 天结算、持久化、测试与平衡工具。

## 约束与原则

- 当前分支 `main`，初始仓库无提交，无现有代码需要保留。
- 采用本地 Web 应用；无需服务器、外部大模型或联网服务。
- 数据与界面解耦；成绩不可直接加分；普通模式不暴露隐藏状态。
- 复现性、资源约束、完整百日流程优先于装饰复杂度。

## 关键风险

- 回合中资源重复计费、随机调用顺序与读档轨迹不一致。
- 普通界面意外泄露真实心理或知识数值。
- 作业过载挤占其他科目，需验证其机会成本与成长上界。
- IndexedDB 不可用时需清晰提示，不能假装保存成功。

## 关键实现说明

- `execute` 是模拟唯一入口，先校验后扣费；失败保留原状态与随机序列。
- 所有分数由知识覆盖、熟练度、难度与有界状态波动计算，教学不能直接修改考试记录。
- 日初邻座快照消除学生结算次序优势；学生时间账本的学习与休整之和恒为240分钟。
- 作业先占实际完成所需时间；额外单科安排会挤占其他学科；高负荷累积疲劳与压力。
- 真实状态、观察与教师推测分离，诊断匹配仅影响后续讲评效率，不直接改心理或成绩。
- 普通历史预测只读取已发生考试，不读隐藏知识或未来随机数。
- 存档含真实状态、行动队列、观察、事件冷却与 PRNG，进行格式、校验和结构验证。
- 调试通过独立副本运行，普通保存和排行榜均拒绝 `debug` 数据。
- 历史记录只追加不改写，指令共享不可变记录，避免复制整局历史；整套测试耗时由44.44秒降至最终约9.85秒。
- 修正开发入口重复 React 根导致的热更新问题；入口复用根实例，随后刷新及生产启动验证通过。
- 导入、创建新局与读取均属于本地操作，不注册账号或发布网络服务。
